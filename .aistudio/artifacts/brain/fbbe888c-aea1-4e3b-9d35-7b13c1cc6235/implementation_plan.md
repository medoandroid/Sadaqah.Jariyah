### 3. Key Product Decisions & Trade-Offs

*   **Decision 1: Zero-Logic-Mutation & Pure DOM/CSS Enhancement**
    *   *Chosen Approach*: Apply all visual changes through enhanced CSS classes, DevMeDoAnDrOiD enterprise custom variables, refined tailwind utility compositions, and non-invasive wrapper aesthetics.
    *   *Why*: Eliminates any risk of breaking existing synchronization hooks, offline storage mechanisms, audio playback state, or route parameters.
    *   *Alternatives Considered*: Rewriting page structures from scratch (rejected because it would risk regressing features and audio pipelines).
*   **Decision 2: Hardware-Accelerated 3D & CSS Variable Matrix**
    *   *Chosen Approach*: Implement 3D depth, liquid glassmorphism, and dynamic glare using purely GPU-accelerated CSS properties (`transform`, `opacity`, `backdrop-filter`, `box-shadow`) tied to centralized root tokens.
    *   *Why*: Guarantees rock-solid 60/120 FPS scrolling even on mid-tier mobile devices, eliminating any layout thrashing.
    *   *Alternatives Considered*: Heavy JavaScript WebGL canvas loops (rejected due to battery consumption on mobile and potential conflicts with text selection in the Quran).
*   **Decision 3: Asymmetric Bento Grid Architecture**
    *   *Chosen Approach*: Group homepage cards and functional tools into an intentional, high-contrast Bento grid where visual rank guides the eye effortlessly from prayer times to personal wird, dedication, and Quran reading.
    *   *Why*: Avoids repetitive card clones and generic AI template repetition while respecting the Anti-Slop constitution.
